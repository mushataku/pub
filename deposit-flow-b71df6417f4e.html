業者の入金がナゲバンの残高に入るまで

拓也へ。2026年11月11日（水）0時30分 時点のコードと本番の記録で書いた。時刻はすべて日本時間（JST）。

要点

拓也がこれを読み終えたら「入金が残高に入らないとき、どの段を疑うか」を自分で言える、を目指した1枚。

  1. 入金は 7つの段を通る。銀行（PayPay銀行）とメール（Gmail）は外の段、④の起こし役から先がこちらの段。
  2. 遅れの正体は ④「読み手を誰が起こすか」。11月10日のテラコヤの 100,000円は④の push が来ず、着金から残高まで33分（人が手で起こした）。この回は業者の「支払いました」も無かった。11月8日は「支払いました」の後の撃ち直しで起きたとみられ（起こした側のログは未確認）、9分38秒。
  3. ④の外れ2つは 11月10日〜11日0時03分に直した（中身は「標準の形からの外れ」）。実際の入金で push が読み手を起こすかは次の入金でまだ確かめていない。

全体図

外の段（業者・銀行・Gmail） こちらの段（ナゲバン） 直した標準の形から外れていて、直した段 未まだ外れている段

各段（何をする・入力→出力・止まるとどうなる・保険）

  1. ①業者が振込 業者

    何をする
    業者コンソールの入金待ちの欄（「PayPay」「銀行振込」）を見て、拓也の PayPay銀行の口座へ振り込む。
    入力→出力
    業者の口座 → 振込（振込名義のカナ付き）
    止まると
    法人口座から振ると振込名義が登録外になりうる（⑥で照合できない）。
    保険
    業者が「支払いました」を押すと、申告の額と時刻が残る（⑥の照合と④の起こしに使う）。

  2. ②PayPay銀行に着金 銀行

    何をする
    口座に入金が載る。明細に「誰が・いくら・取引番号」。
    入力→出力
    振込 → 明細の1行・アプリの入金通知
    止まると
    銀行側の遅れはこちらから見えない（実績では着金→メールが1分30秒〜2分49秒）。
    保険
    なし（外の段）。

  3. ③alumni の受信箱に「振込入金のご連絡」 Gmail

    何をする
    入金があったと最初に知らせてくる口。本文は入金日時だけで、金額も名義も無い（11月10日に本文全体を確認）。
    入力→出力
    着金 → メール1通。受信箱のフィルタ「通知/金融」がラベルを付け、受信トレイから外す。
    止まると
    メールが来ないと④が起きない。メールだけでは残高に足さない（額を推測しない）。
    保険
    ⑤の定期（4時間おき）が Gmail を検索して拾う。

  4. ④起こし役（Gmail watch → push の受け口） 直した 外れ1・2

    何をする
    Gmail の watch がメールの到着を Pub/Sub に流し、受け口 /bank-push が受け取って⑤の読み手 Job を起こす。起こすだけで残高には触らない。
    入力→出力
    入金メールの到着 → 読み手 Job の起動1回
    止まると
    ⑤が次の保険（4時間おきの定期か「支払いました」）まで起きない＝遅れの大半はここ。11月10日はこれで33分（手で起こした）。
    保険
    ⑤の定期（4時間おき）／業者の「支払いました」の直後と、その後30分の撃ち直し／旗 ALERT_paypay_bank_unread（メールは来たのに30分たっても入口に行が無い）／旗 ALERT_paypay_bank_watch_expired（watch の期限切れ）。
    11月10日〜11日に2つ直した（中身は「標準の形からの外れ」）。実際の入金で push が読み手を起こすかは、まだ確かめていない（次の入金で確かめる）。

  5. ⑤読み手 Job（bot-lab-paypay-reader）

    何をする
    クラウドから遠隔で Pixel につなぎ、PayPay銀行アプリの通知を読む。通知で足りなければアプリを開いて明細を読み、閉じる。
    入力→出力
    Pixel の通知・明細 → 入口 bank_inbox.jsonl に1件1行（時刻・名義・金額）→ すぐ⑥を起こす
    止まると
    Pixel がつながらない・銀行アプリがログアウト・画面が読めない。PayPay銀行アプリは同時に1台しかログインできない。
    保険
    旗 ALERT_paypay_bank_unread（メールは来たのに30分たっても入口に行が無い）／旗 ALERT_paypay_reader_offline（Pixel かアプリにつながらない状態が30分続く）。どちらも Discord の claude チャンネルに拓也宛てで届く。

  6. ⑥受付段が照合して残高へ

    受付段＝MNP タイプBの依頼を受け付けて、残高を出し入れする係（⑥と⑦は同じ係）。

    何をする
    入口の行の振込名義を、業者ごとの登録名義と完全一致で照らし、当たった業者の台帳 balance/ に足す（credit）。
    入力→出力
    入口の1行 → 台帳の credit 1件（業者の残高が増える）
    止まると
    名義が登録外・2業者に当たる → 足さずに「照合できない入金」へ（Discord に知らせる）。
    保険
    業者の「支払いました」と同額・前後30分以内がちょうど1件なら自動で足し、その名義を覚える。それ以外は管理が業者コンソールで割り当て（1タップ・名義も覚える）。

  7. ⑦依頼が進む

    何をする
    残高から依頼の分（回線の数×単価）を引き（charge）、依頼を次の段へ進める。
    入力→出力
    残高 → charge 1件・依頼の段が進む
    止まると
    残高が足りない（入金待ちの表示が「あと ○円」のまま）。
    保険
    受付段の定期（10分おき）が拾い直す。

標準の形からの外れ（3つ）

段外れ標準の形いま
④watch が受信トレイ（INBOX）だけを見る。フィルタで受信トレイを外れる入金メールでは push が出ない入金メールが付くラベルも watch する直した 11月11日 0時03分に張り直し。実入金での確認は次の入金（票 bank-watch-follow-inbox-filter-prod-check）
④push の中身（どこまで読んだかの番号＝historyId）を見ず、直近1時間を検索＋10分の時間窓で判断。LinksMate の受け口も同じ形だった番号から history.list で増えたメールだけを引く直した 11月10日 19時台にデプロイ（票 bank-push-history-list）
④〜⑦各段の時刻が構造的に残らない（この図の時刻は、ログと台帳とメールを後から突き合わせた）入金1件ごとに段の時刻を1行で持つ未 票 deposit-latency-timeline

止まったとき疑う順

症状ごとに、上から順に段を疑う。「見る口」は画面か旗の名前。旗は Discord の claude チャンネルに、拓也宛ての知らせとして旗の名前で届く。

業者が「振り込んだ」と言うのに、残高が増えない

  1. ①業者が「支払いました」を押したか見る口: 業者コンソールの申告。押していなければ④の撃ち直しも⑥の自動照合も動かない
  2. ②着金したか見る口: 司令塔（Claude）に「②の明細を見て」と頼む。自分の端末で PayPay銀行アプリにログインしない（同時に1台しかログインできず、Pixel の読み手が追い出される）。着金が無ければ業者側か銀行側
  3. ③メールが来たか見る口: alumni の Gmail のラベル「通知/金融」に「振込入金のご連絡」（受信トレイには出ない）
  4. ④⑤読み手が起きて読めたか見る口: 旗 ALERT_paypay_bank_unread（メールの30分後に立つ）・ALERT_paypay_reader_offline（Pixel かアプリにつながらない）。急ぐなら、業者コンソールに管理として業者の立場で入り、入金待ちの「支払いました」を押す（読み手がすぐ起き、30分のあいだ撃ち直す）か、司令塔に「読み手を1回起こして」と頼む
  5. ⑥照合できたか見る口: Discord の「照合できない入金」・業者コンソール（管理）の照合できない入金の一覧 → 業者に割り当て（1タップ）

Discord に「照合できない入金」が来た

  1. ⑥振込名義が登録外（法人口座・家族名義など）見る口: 業者コンソール（管理）で割り当てる。割り当てた名義は覚えるので次からは自動
  2. ⑥名義が2つの業者に当たる見る口: 業者コンソール（管理）で割り当てる
  3. ①業者の「支払いました」が無い・額が違う見る口: 業者コンソールの申告。同額・前後30分以内がちょうど1件なら自動で足す

旗 ALERT_paypay_bank_unread が立った（メールは来たのに30分読めない）

  1. ④起こし役が起こしていない見る口: 旗 ALERT_paypay_bank_watch_expired（watch の失効）。無ければ受け口が起こせていない
  2. ⑤読み手が読めない見る口: 旗 ALERT_paypay_reader_offline・Pixel がつながっているか・PayPay銀行アプリが別の端末でログインされていないか

残高は増えたのに、依頼が進まない

  1. ⑥本当に残高に入ったか見る口: 業者コンソールの残高（台帳の入金の行）
  2. ⑦残高が依頼の分に足りない見る口: 業者コンソールの入金待ちの表示（「あと ○円」）
  3. ⑦受付段が止まっている見る口: 業者コンソールの依頼の段（10分たっても動かないか）・Discord の claude チャンネルの受付段の見張りの知らせ

PayPay 送金（kosei など）が残高に入らない

  1. Pixel に PayPay の「受け取り完了」の通知が来たか見る口: 旗 ALERT_paypay_needs_check（読めない通知・同額の重なり）
  2. PayPay がログアウトしていないか見る口: 旗 ALERT_paypay_reader_offline（理由「PayPay がログアウトしている」）
  3. ⑥表示名が登録外見る口: Discord の「照合できない入金」→ 業者コンソールで割り当て
