Linuxの復習（高橋さん）

11月11日　高橋さんへ　／　株式会社SeeD 武者野　／　面接で「サーバーを立てた話」を聞かれたときのための整理

先に結論：面接までに、次の3つを自分の言葉で言えるようにしておきましょう

  1. 何の上で、何を動かしたか（例：自宅のPCに仮想マシンを作り、Ubuntu を入れて、Webサーバーを動かした）
  2. よく使うコマンド2〜3個と、何のために使ったか（例：systemctl status でWebサーバーが動いているか確かめた）
  3. つまずいたところと、どう乗り越えたか（例：最初はコマンドが何も分からなかったが、ChatGPT と教科書で一つずつ調べた）

高橋さんがやったことを、言葉と流れで整理し直したページです。分からない言葉があれば、2. から読んでください。

1. 高橋さんがやったことの全体像

高橋さんが話してくれた「Linuxで仮想サーバーを立てて、ホームページが見られるか確かめた」は、仕組みで言うと次の4段の積み重ねです。下から順に積んで、一番上のブラウザで画面が出たら成功です。

  • ④ ブラウザ：Chrome などで開いて、ホームページが表示されるか確かめる
  • ③ Webサーバー（nginx や Apache）：ホームページを配るソフト
  • ② Linux（Ubuntu など）：仮想のPCに入れたOS
  • ① 仮想マシン（VirtualBox など）：自宅のPCの中に作った、もう1台のPC

上の図は、上が最後の確認、下が土台です。

面接で「どんな環境で？」と聞かれたら、この4段を下から言えば十分に伝わります。ソフトの名前（VirtualBox・Ubuntu・nginx など）は、高橋さんが実際に使ったものに置き換えてください。名前を思い出せないときは、仮想マシンのソフトを開けば画面に出ています。

2. 言葉の整理

仮想マシン（VirtualBox など）

自分のPCの中に、ソフトで作ったもう1台のPCを動かす仕組みです。Windows の画面の中にウィンドウが1つ開き、その中で別のOSがまるごと動きます。PCを買い足さずに練習台が手に入り、設定を間違えても消して作り直せます。同じ種類のソフトに VMware や Windows 標準の Hyper-V があります。仕事で使うクラウド（AWS など）のサーバーも、仕組みとしてはこの延長です。

Linux と Ubuntu

Linux はOSの中心の部分だけを指す言葉です。それに画面・コマンド・ソフトを入れる仕組みなどを一式まとめて、すぐ使えるOSにしたものを「ディストリビューション（配布版）」と呼びます。Ubuntu はその1つで、一番よく使われています。

たとえると、Linux がエンジンで、Ubuntu はそのエンジンを積んだ車の車種です。ほかの車種に、企業のサーバーで定番の Red Hat Enterprise Linux や、そこから生まれた Rocky Linux・AlmaLinux があります。

日本の企業のサーバーは Red Hat 系が多いですが、LinuC の試験は種類に寄らない内容です。Ubuntu で練習したことは、そのまま話して大丈夫です。

Webサーバー（nginx・Apache）

ブラウザから「このページをください」と頼まれたら、ホームページのファイルを返すソフトです。nginx（エンジンエックス）と Apache（アパッチ）が二大定番です。高橋さんが「ホームページが見られた」のは、このソフトが仮想マシンの中で動いていたからです。

IPアドレス

ネットワークの中での住所です。仮想マシンにも住所が割り当てられていて、ブラウザにその住所を打ち込むと、仮想マシンの中のWebサーバーに届きます。

3. サーバーを立てた流れ（Ubuntu と nginx の例）

ChatGPT に教わった手順も、だいたいこの流れだったはずです。一つずつ、何のために打つのかを言えるようにしておくと、面接での説明が具体的になります。

  1. ソフトの一覧を新しくする 
    sudo apt update
    sudo は「管理者の権限で実行する」、apt は Ubuntu でソフトを入れる道具です（Red Hat 系では dnf）。
  2. Webサーバーを入れる 
    sudo apt install nginx
  3. 動いているか確かめる 
    systemctl status nginx
    緑の文字で active (running) と出ていれば動いています。止まっていたら sudo systemctl start nginx で起動します。
  4. 仮想マシンの住所（IPアドレス）を調べる 
    ip a
    inet 192.168.… のように出る数字が住所です。
  5. まず仮想マシンの中から確かめる 
    curl localhost
    ホームページの中身（HTML の文字）が返ってくれば、Webサーバーは正しく動いています。
  6. ブラウザで開く：調べた住所をブラウザに打ち込み、「Welcome to nginx!」などのページが出たら成功です。

見えないときに確かめる順番（インフラの仕事そのものです）

  1. systemctl status で、Webサーバーが動いているか
  2. curl localhost で、中からは見えるか
  3. 中から見えて外から見えないなら、通信の通り道（仮想マシンのネットワークの設定・ファイアウォール）を疑う

高橋さんが面白いと話していた「問題なく動いているかを確かめる」は、まさにこの順番で原因を絞っていく作業です。

5. 履歴を見るコマンド

自分が今まで打ったコマンドは、Linux が覚えています。面接の前に一度見返すと、自分が実際によく使ったコマンドが分かります。

やりたいこと操作
打ったコマンドを一覧で見るhistory（直近20件だけなら history 20）
1つ前のコマンドに戻るキーボードの ↑
過去のコマンドを文字で探すCtrl＋R を押してから文字を打つ
一覧の番号でもう一度実行する!105（105番を実行）
誰がいつログインしたかlast
システムやソフトの動作記録journalctl -u nginx（nginx の記録だけ）
Webサーバーへのアクセスを流れるまま見るtail -f /var/log/nginx/access.log（止めるのは Ctrl＋C）

ブラウザでページを開いた瞬間に tail -f の画面へ1行増えるのを見ると、「ブラウザの頼みがサーバーに届いた」ことが目で分かります。時間があればやってみてください。

6. 面接での言い方

前回の練習と同じく、はじめの一言を10秒で言い、聞かれたら付け足す形です。下の例のソフトの名前は、高橋さんが使ったものに置き換えてください。

Q. どんな環境でサーバーを立てたんですか？「自宅のPCに VirtualBox で仮想マシンを作り、Ubuntu を入れて、nginx でWebサーバーを立てました。ブラウザでページが表示されるところまで確かめました。」
Q. 一番使うコマンドは何ですか？「systemctl status です。Webサーバーが動いているかを確かめるのに、一番よく使いました。」
Q. 一番難しかったところは？「コマンド入力です。最初は何も分からなかったので、ChatGPT と教科書で一つずつ意味を調べながら進めました。」
  • コマンドは名前と、何のために使ったかをセットで言います。名前だけより、ずっと「本当に触った人」に聞こえます
  • 答えにするコマンドは、history で実際に打ったものから選ぶのが一番です。自分で使ったものなら、深掘りされても答えられます
  • 分からないことを聞かれたら、「そこはまだ触れていません。次は〇〇を触ってみたいと思っています」と答えれば大丈夫です。次は AWS を触りたい、という高橋さんの話につなげられます

7. 確認クイズ（答えは押すと開きます）

Q1. Linux と Ubuntu の関係は？

Linux はOSの中心の部分で、Ubuntu はそれを一式まとめて使える形にした配布版（ディストリビューション）の1つ。エンジンと車種の関係です。

Q2. 仮想マシンを使う良いところは？

PCを買い足さずに練習台が手に入り、間違えても消して作り直せること。元のPCには影響しません。

Q3. Webサーバーが動いているかを確かめるコマンドは？

systemctl status nginx（Apache なら systemctl status apache2）。active (running) と出れば動いています。

Q4. 自分の住所（IPアドレス）を調べるコマンドは？

ip a

Q5. 中からは見えるのにブラウザから見えないとき、どこを疑う？

Webサーバー自体は動いているので、通信の通り道（仮想マシンのネットワークの設定・ファイアウォール）を疑います。

Q6. 今まで打ったコマンドを一覧で見るには？

history。過去のコマンドを文字で探すなら Ctrl＋R。
