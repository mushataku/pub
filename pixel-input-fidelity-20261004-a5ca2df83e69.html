Pixel の入力の出どころは、ページからどう見えるか

自陣の localhost ページを Pixel の Chrome で開いて測定（実サイトには触っていない）。各図の棒＝平均・黒線＝±SE（標準誤差）。

結論3つ（2026-10-04 19:23 JST・Pixel 実機・縦向き・Chrome・各押す腕 n=10・20字の文字列）

  • (a) 押下の既定＝CDP のタッチ（P2）。adb tap は予備。どの腕もページには isTrusted の本物の事象で、touch 系（P2・P3・P4）は pointerType=touch・順番も同じ（pointerdown→touchstart→pointerup→touchend→mousedown→mouseup→click）。差は細部: adb の tap／swipe は半径 radiusX=0・PointerEvent.width=0（接触面積が無い）、tap は押している時間が約1ms（P4 の swipe 80ms で伸ばせる）。CDP のタッチは半径1・幅2（これも既定値の小ささ）・押下70〜80ms。CDP は半径・force・時間を引数で指定できるが adb は指定できない＝調整できる P2 を既定にする。P1（今の TOUCH の押し方＝CDP マウス）は pointerType=mouse・touch 事象ゼロで、スマホとして不自然＝並走票の変更は妥当。未実測: 人の指（P0）の値。半径が人で 0 でないことは一般知識からの推論。P2 の半径・force を上げたときに実際に値が変わるかも未確認（次の一手）。
  • (b) 打鍵の既定＝K2（adb input text・1字ずつ）。K2・K3 は keyCode 229・inputType=insertCompositionText・composition 事象ありで、スマホのソフトキーボードと同じ見え方。K1（CDP keyboard.type）は keyCode が実字（65…）・insertText・composition 無しで、PC の打鍵に見える。字間隔は K1 が 135±1ms（揃いすぎ）、K2・K3 は約240±19ms（adb の呼び出し遅延で揺れる）。K2 は ASCII だけ。K4（Gboard の鍵を押す）は [未到達]＝通常の dump には鍵が出ず、uiautomator dump --windows で出るが、端末の鍵盤が日本語12キー（あ〜わ）で a〜z の鍵が無い。注意: K2・K3 は入力欄の最終長が 14/20 で、composition のため読み戻しで確かめる必要がある。
  • (c) 「ケーブル無し」（uiautomator で読んで adb で押す）は成り立つ。dump にページの見出しの文字（PIF 見出し probe）・ボタンの aria-label（content-desc）・HTML の id（resource-id=…tgt）と bounds が出る。出ないもの: ボタンの表示文字（aria-label があるとそちらに置き換わる）・入力欄の aria-label（編集欄は別の出方）。鍵盤は --windows が要る。接続の痕跡: CDP を挿していても navigator.webdriver=false・window の自動化変数なし・Error stack getter の手は C1・C2・C3 とも 0 回。ただしデスクトップの playwright（Chrome 148）でも 0 回＝この手はもう効かない（検出力なし）ので「痕跡なし」の証拠にはならず、「この手では分からない」まで。
