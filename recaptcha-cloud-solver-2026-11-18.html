結論

クラウド（GCP のデータセンター IP）でも音声で解けば通る: 音声込みのトークン取得は headed 15/16・headless 15/16（2腕合わせて 30/32＝0.94・Wilson 95% 0.80〜0.98）で、PC の家回線の 13/15＝0.867 と差は無い（Fisher p=0.58）。2腕の差も無い（p=1.0）。一方、チャレンジ無しの即時通過は 0/32（95% 上端 0.11）で、PC の家回線の行 C の 27/64＝0.42 から大きく落ちた（Fisher p<0.001）＝クラウドの出口では毎回音声のチャレンジが出るが、出たものはほぼ解ける。blocked（自動クエリ）は各腕 1/16。

逐次の打ち切り: cut_by_hand（腕あたり 16 回・n=16 は more（両腕 15/16・PC の base と区別がつかない）。32 まで撃つと task-timeout 7200s に当たる見込み（1回 約2.1分）で手で止めた）

読み方と次

n=16 の判定は more（両腕とも base と区別がつかない）で、32 まで撃つと Job の task-timeout（2時間）に当たる見込みだったため手で止め、判定の時点の件数を結果にした（以後の実行は持ち時間 6300 秒で自分で止まる）。即時通過が 0 になったのが出口（IP）のせいか、新しいプロファイル・SwiftShader のせいかはこの2腕では切り分けられない。切り分けるなら同じ箱で出口だけ変える腕（住宅 IP＝課金ゲート）が要る。音声で解ける限り、クラウドの解き手は PC の家回線の代わりになる。
