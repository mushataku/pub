exit node 越しの reCAPTCHA：封じを1つずつ外しても即時通過は戻らなかった（2026-11-18 夕方）

クラウド（Cloud Run Job）から家の PC を exit node にして、公開の的を開いたときの reCAPTCHA の即時通過を、3つの封じ（audio・dns・webrtc）を1つずつ外した5腕で撃ち比べました。朝は 13/16 通っていたのに、昼に封じを入れてから 6/16 に落ちていました。夕方の撃ちでは、封じを全部外した腕も 1/15 で、封じの有無で差は見えませんでした。

1. 結論

  • 封じを全部外した腕（1/15）と全部塞いだ腕（1/14）の差は −0.005、95% 区間は [−0.254, +0.234] でした。1つだけ外した3腕も、全部塞ぐとの差は −0.07〜0.00 で、区間はどれも 0 をまたぎます。
  • 朝の撃ち（13/16）と比べると、今回の5腕はどれも 0.74〜0.81 低く、区間は 0 にかかりません。下がったぶんは、封じとは別のところで起きています。
  • 音声を解いたあとのトークンは 5腕とも 12/15〜15/15 で、最後まで通る割合はそれほど落ちていません。落ちたのは「チェックを押した瞬間に通る」割合のほうです。
  • この撃ちで見分けられる差の目安は約 0.52 です（腕ごとに n≈15）。0.5 より小さい差は、この本数では見えません。

5. 段B（携帯の回線）

段B は、人材用の黒7a（携帯の回線）を exit node にして同じ撃ちをする段です。

  • 診断（1回・15:40）：出口の照合は通りました（AS4686・端末の Wi-Fi を切って読んだ IP と一致）。経路は中継（DERP・東京）のままで、直の経路はつながっていません。curl で IP 確認の口と的の健康の口はどちらも 200（0.58 秒・0.56 秒）、ヘッドレスの Chrome でも 200 でした（6.4 秒・2.9 秒）。前の票で出た SOCKS の接続失敗は、この診断では出ませんでした。
  • 撃ち1（15:47）：出口の照合で止まりました（AS2514＝家の回線）。端末の Wi-Fi が戻った状態で撃っていたためで、試行は0回です。
  • 撃ち2（15:51）：照合は通りましたが、15:54 に携帯の回線の使用量の番人が止めました（15:38 からの増分 132MB）。試行は0回です。止めたあとの増分は 161.6MB で、上限の 100MB を超えました。15:50 時点の増分は 7.4MB でした。

段B の撃ちはできていません。数字は段A（家の PC が出口）だけです。
