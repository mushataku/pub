GitHubを始めるまではじめに

高木さんへ　GitHubを始めるまで（Windows）

11月20日（金）　／　株式会社SeeD 武者野

gitとGitHubがそれぞれ何か（仕組み）は、「gitとGitHubのちがい」のタブにまとめています。

このタブは手を動かす方です。上から順に進めれば、GitHubのアカウントを作ってから、最初のファイルをGitHubに上げて確かめるところまで行けます。初めてなら1時間ほどを見ておいてください。ステップごとに、画面で押すところ・打つコマンド・うまくいったときの見え方を書いています。

  1. 1アカウントを作る
  2. 2Git for Windows を入れる
  3. 3名前とメールを登録
  4. 4リポジトリを作る
  5. 5最初の commit と push
  6. 6確かめる

最初に1つだけ約束　パスワード・2段階認証の6桁の数字・回復用コード（後で出てきます）は、GitHubの画面以外には打ち込まないでください。Git Bash（黒い画面）にも、LINEにも、スクリーンショットにも載せません。困ったときに送ってもらうのは、画面に出た英語のメッセージだけで大丈夫です。

1. GitHubのアカウントを作る

画面で押すところ
  1. ブラウザで github.com を開き、右上の「Sign up」を押す
  2. メールアドレス・パスワード・ユーザー名を入れ、国（Japan）を選んで「Continue」
  3. 人間かどうかの確認（簡単なパズル）に答える
  4. メールに届いた確認コードを入れる
  5. ログイン画面が出たら、いま決めたユーザー名とパスワードでログイン
うまくいったときの見え方

左に「Create your first project」などの案内が並ぶ、GitHubのトップ画面（ダッシュボード）が出ます。料金プランを聞かれたら「Free」で十分です。

2段階認証（2FA）を設定しておく

GitHubは、コードを置く人に2段階認証を求めています。ログインのたびに、パスワードに加えてスマホのアプリに出る6桁の数字を入れる仕組みです。後から「設定してください」という案内が届き、期限（45日）を過ぎると使えなくなるので、最初に済ませておきます。

画面で押すところ
  1. スマホに認証アプリを入れておく（「Google Authenticator」や「Microsoft Authenticator」など。無料）
  2. GitHubの右上の丸いアイコン →「Settings」→ 左の「Password and authentication」
  3. 「Enable two-factor authentication」を押す
  4. 画面に出たQRコードを、スマホの認証アプリで読み取る
  5. アプリに出た6桁の数字を、GitHubの画面に入れる
  6. 回復用コード（Recovery codes）が出るので「Download」して保存する
うまくいったときの見え方

「Password and authentication」の画面で、Two-factor authentication の欄が「Enabled」になります。次にログインするとき、パスワードの後に6桁の数字を聞かれるようになります。

2. Git for Windows を入れる

gitを自分のPCに入れます。Windows用は「Git for Windows」という名前で配られていて、黒い画面の「Git Bash」と、push のときにログインを肩代わりする仕組み（Git Credential Manager）も一緒に入ります。

画面で押すところ
  1. ブラウザで git-scm.com を開き、「Install」→「Windows」へ進む
  2. 「Click here to download」を押す（ふつうのPCはこれ。ARM版のPCなら下の一覧から「ARM64」）
  3. ダウンロードした Git-…-64-bit.exe を開き、「このアプリがデバイスに変更を加えることを許可しますか？」は「はい」
  4. 画面が何枚も続きます。基本は初めから選ばれているまま「Next」。次の2か所だけ変えておくと後で楽です

画面の順番や言い回しは、版によって少し変わることがあります。分からない画面は、初めから選ばれているままで進めてください。

打つコマンド

スタートメニューで「Git Bash」を探して開き、次を打って Enter を押します。

git --version
うまくいったときの見え方 
git version 2.56.1.windows.1

数字は入れた時期で変わります。git version で始まる1行が出れば成功です。Git Bash では、貼り付けは右クリック→「Paste」か Shift＋Insert です（Ctrl＋V では貼れないことがあります）。

3. 自分の名前とメールアドレスを git に登録する

記録（コミット）ごとに「誰が記録したか」が残ります。その名前とメールアドレスを最初に1回だけ登録します。

画面で押すところ（先にメールアドレスを用意）

ここで登録したメールアドレスは、GitHubに上げた記録の中で誰でも見られます。表に出さないために、GitHubが用意してくれる公開用の代わりのアドレスを使います。

  1. GitHubの右上のアイコン →「Settings」→ 左の「Emails」
  2. 「Keep my email addresses private」に印を付ける
  3. その説明文の中に出る （数字）+（ユーザー名）@users.noreply.github.com の形のアドレスをコピーする
打つコマンド

Git Bash で1行ずつ打ちます。" " の中を自分のものに置き換えます。名前は半角英字がおすすめです。

git config --global user.name "Takagi"
git config --global user.email "コピーした noreply のアドレス"

入ったか確かめます。

git config --global --list
うまくいったときの見え方 
user.name=Takagi
user.email=（数字）+（ユーザー名）@users.noreply.github.com

ほかに数行（init.defaultbranch=main など）が並んでいても問題ありません。何も出ずに次の行に戻るのは、打ったコマンドが正しく通ったという意味です。

4. GitHub でリポジトリを作る

GitHub側に、記録を置く入れ物（リポジトリ）を作ります。名前は、Pythonの練習と同じ python-practice にします。

画面で押すところ
  1. GitHubの右上の「＋」→「New repository」
  2. 「Repository name」に python-practice
  3. 公開範囲は Public（面接で見せるため。誰でも見られます）
  4. 「Add README」をオンにする（リポジトリの表紙になる説明ファイル）
  5. 「Create repository」
うまくいったときの見え方

github.com/ユーザー名/python-practice のページが開き、ファイルの一覧に README.md が1つだけあります。本線の名前の欄には main と出ています。

5. 最初の1回の commit と push

GitHubのリポジトリを手元に持ってきて（clone）、ファイルを1つ足し、記録して（commit）、GitHubへ上げます（push）。足すファイルは、Pythonの練習の最初に作った hello.py です。

5-1. 手元に持ってくる（clone）

画面で押すところ

リポジトリのページで緑の「Code」→「HTTPS」→ URLの右のコピーのボタン。

打つコマンド 
# ユーザーのフォルダ（C:\Users\…）へ移る
cd ~
# コピーしたURLを貼る
git clone https://github.com/ユーザー名/python-practice.git
cd python-practice

デスクトップはOneDriveの同期がかかっていることがあり、gitの記録とぶつかることがあるので、ユーザーのフォルダに置きます。デスクトップにあるPythonの練習のフォルダとは別のフォルダになります。

うまくいったときの見え方 
Cloning into 'python-practice'...
remote: Enumerating objects: 3, done.
…
Receiving objects: 100% (3/3), done.

Public のリポジトリなので、ここではまだログインは聞かれません。

5-2. ファイルを1つ入れる

打つコマンド 
# いまのフォルダをエクスプローラーで開く（最後の点まで打つ）
explorer .
画面で押すところ

開いたフォルダ（README.md が入っている）に、デスクトップの python-practice フォルダから hello.py をコピーして貼り付けます（右クリック→コピー、貼り付け先で右クリック→貼り付け）。

5-3. 記録して（commit）、上げる（push）

打つコマンド 
# 何が変わったかを見る
git status
うまくいったときの見え方 
Untracked files:
        hello.py

「まだ記録していない新しいファイルがある」という意味です（赤い字で出ます）。

打つコマンド 
git add hello.py
git commit -m "最初のPythonファイルを追加"
git push

-m の後ろの文が、この記録のメモになります。git commit の後に 1 file changed と出れば記録できています。

画面で押すところ（初めての push のときだけ）

git push を打つと「Connect to GitHub」という窓が開きます。これが Git Credential Manager です。「Sign in with your browser」を押し、ブラウザで開いたGitHubの画面で許可（Authorize）を押します。2段階認証の6桁も、聞かれたらブラウザの画面に入れます。

うまくいったときの見え方 
To https://github.com/ユーザー名/python-practice.git
   1a2b3c4..5d6e7f8  main -> main

最後の main -> main が「手元の main を GitHub の main へ上げた」という意味です。英数字の部分は人によって違います。

6. 上がったか確かめる

画面で押すところ

ブラウザで github.com/ユーザー名/python-practice を開き直す（F5 で再読み込み）。

打つコマンド（手元でも確かめる） 
git log --oneline
git status
うまくいったときの見え方 
5d6e7f8 (HEAD -> main, origin/main) 最初のPythonファイルを追加
1a2b3c4 Initial commit

On branch main
Your branch is up to date with 'origin/main'.
nothing to commit, working tree clean

origin/main はGitHub側のことです。手元とGitHubが同じ記録まで来ていて（up to date）、まだ記録していない変更も無い（clean）、という意味です。

ここまで来たら、最初の1回は完了です。おつかれさまでした。

7. 宿題　Pythonの練習の成果を置いてみる

このタブの最後は宿題です。「Pythonの練習」のタブで書いた残りのファイルを、いまのリポジトリに置きます。手順は5-2と5-3のくり返しです。

画面で押すところ

デスクトップの python-practice から、名前の最後が .py のファイル（make_data.py・count.py・make_days.py・update_list.py など）を、ユーザーのフォルダの python-practice にコピーします。練習で作られたExcelのファイル（.xlsx）と「毎日」フォルダはコピーしなくて大丈夫です（コードを動かせば何度でも作れるため）。

打つコマンド 
cd ~/python-practice
git status
git add .
git commit -m "Pythonの練習（課題1・課題2）を追加"
git push

git add . の最後の点は「このフォルダの変更を全部」という意味です。git status で、入れたいファイルだけが並んでいるのを先に確かめてから打ちます。

うまくいったときの見え方

GitHubのページを開き直すと、.py のファイルが並び、上の帯に「Pythonの練習（課題1・課題2）を追加」が出ます。

仕上げ：README に2〜3行書く

GitHubの画面で README.md を開き、右上の鉛筆のマークから「何の練習か」を2〜3行書いて「Commit changes」を押します。VBAで何をしていたか → それをPythonでどう書き直したかが一言あるだけで、前職の経験とつながった勉強だと伝わります。

GitHubの画面で直した後は、手元をそろえるために、次に作業を始めるとき Git Bash で git pull を1回打ちます。この先の練習は、ユーザーのフォルダの python-practice で続けると、直すたびに add・commit・push するだけで済みます。

置けたら、リポジトリのURL（https://github.com/ユーザー名/python-practice）をLINEで送ってください。面接の前に一緒に見て、見せ方を考えます。

8. つまずきやすい所

「Please tell me who you are」と出てコミットできない

手順3の登録がまだです。手順3の2行を打ってから、もう一度 git commit すれば通ります。

push が断られる（ログインに失敗する・403 と出る）

GitHubのパスワードを Git Bash に打っても通りません。ブラウザの画面で許可するのが正しい流れです。別のアカウントで一度ログインしてしまった場合は、Windowsの「資格情報マネージャー」を開き、「Windows資格情報」の中の git:https://github.com を削除してから、もう一度 git push するとログインの窓が出直します。

push が「rejected」で断られる（GitHubの画面で README を直した後など）

GitHub側に、手元にない新しい記録があるという意味です。先に git pull で取ってきてから git push すれば通ります。仕組みは「gitとGitHubのちがい」の4段目に図があります。

「not a git repository」と出る

いる場所がリポジトリのフォルダの外です。cd ~/python-practice で中に入ってから打ち直します。いまどこにいるかは pwd で確かめられます。

git commit を打ったら、見慣れない画面やメモ帳が開いた

-m "メモ" を付け忘れると、メモを書くための画面が開きます。メモ帳なら、1行目にメモを書いて保存して閉じれば記録されます。黒い画面（Vim）が開いた場合は、Esc を押してから :q! と打って Enter で抜け、-m を付けて打ち直します。

2段階認証の6桁を入れても通らない

数字は30秒ごとに変わります。アプリに出ている最新の数字を入れ直してください。スマホの時刻がずれていても通らないので、時刻の自動設定がオンかも確かめます。

Publicのリポジトリは誰でも見られます。パスワード・回復用コード・社外秘のデータ・前職のファイルそのものは置かないでください。置くのは自分で書いた練習のコードだけにします。

分からないところで止まったら、出ている英語のメッセージをそのままLINEで送ってください（パスワードや数字は送らないでください）。どこで止まっているか一緒に見ます。
