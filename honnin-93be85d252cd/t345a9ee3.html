GitHubのはじめかたはじめに

高木さんへ　GitとGitHubのはじめかた

1. Gitとは　ファイルの「セーブポイント」を残す道具

VBAのマクロを直すとき、壊すのが怖くて _v2 _最終 _最終2 とファイルをコピーしていった経験はないでしょうか。Gitは、あのコピーをファイル1つのままやってくれる道具です。

ゲームのセーブポイントと同じで、「ここまでうまく動いた」という時点に名前を付けて記録しておけます。あとで壊しても、記録した時点へいつでも戻れます。記録ごとに「何を変えたか」のひとことメモも付くので、半年後に見返しても経緯が分かります。

2. GitHubとは　Gitの記録を置くネット上の場所

Gitは自分のパソコンの中で動く道具です。GitHub（ギットハブ）は、その記録をネット上に置いておくサービスです。Gitが「セーブ機能」なら、GitHubは「セーブデータを預けるクラウド」にあたります。名前が似ていますが、別のものです。

転職でポートフォリオになる理由

IT職の面接では「Pythonを勉強しています」と言うより、「これが書いたコードです」とURLを1本見せる方がずっと伝わります。GitHubに置いたコードは、ファイルの中身に加えていつ・どのくらいの頻度で・何を直してきたかの記録まで見えます。毎週少しずつ記録が積み上がっていれば、それ自体が「続けて勉強している」証拠になります。社内SEやDX推進の求人で「GitHubのURLがあれば記入」という欄があるのも、このためです。

3. 用語を図で

最初に覚える言葉は5つだけです。

リポジトリ記録を取る対象のフォルダ。略して「リポ」。
コミットセーブポイントを1つ作ること。メモ付き。
プッシュ手元の記録をGitHubへ上げること。
プルGitHubの新しい記録を手元へ取ってくること。
ブランチ本線から枝分かれして試す道。

リポジトリ　＝　記録付きのフォルダ

コミット → プッシュ → プル

ブランチ　＝　枝分かれして試す

4. 導入の仕方（Windows）

全体の流れはこの6段です。最初の1回だけ手間がかかり、2回目からは手順5〜6のくり返しになります。

  1. GitHubのアカウントを作る

    ブラウザで github.com を開き、「Sign up」から登録します。メールアドレス・パスワード・ユーザー名を決め、届いた確認コードを入れれば完了です。

    ユーザー名はURLになり、面接官の目に入ります。github.com/ユーザー名 の形で表示されるので、名前をもとにした落ち着いたものにしておくと安心です。

  2. Git for Windows を入れる

    git-scm.com を開き、Windows向けのダウンロードからインストーラーを落として実行します。途中でたくさん選択肢が出ますが、全部そのまま「Next」で大丈夫です。入れ終わると、スタートメニューに「Git Bash」が増えます。

    入ったか確かめるには、「Git Bash」を開いて次を打ちます。git version 2.… のように版の番号が出れば成功です。

    git --version
  3. 自分の名前とメールアドレスを Git に登録する

    セーブポイントに「誰が記録したか」を残すための設定です。Git Bash で1行ずつ打ちます（" " の中を自分のものに置き換えます）。

    git config --global user.name "Takagi"
git config --global user.email "GitHubに登録したメールアドレス"

    ここで入れたメールアドレスは、GitHubに上げた記録の中に残ります。表に出したくなければ、GitHubの「Settings」→「Emails」に表示される公開用の代わりのアドレス（noreply の付いたもの）を使えます。

  4. GitHub でリポジトリを作る

    GitHubにログインし、右上の「＋」→「New repository」を押します。名前を付け、「Public」（誰でも見られる）を選び、「Add a README file」に印を付けて「Create repository」を押します。

    GitHubで作ったリポジトリの本線は、最初から main という名前になっています。

  5. 手元に持ってくる（clone）

    作ったリポジトリのページで緑の「Code」ボタンを押し、「HTTPS」に出ているURLをコピーします。

    Git Bash を開き、置きたい場所へ移ってから git clone にURLを貼ります（Git Bash では右クリック→「Paste」で貼れます）。

    # 例：ドキュメントの中に置く
cd ~/Documents
git clone https://github.com/ユーザー名/python-practice.git
cd python-practice

    ドキュメントの中に python-practice フォルダができます。これが手元のリポジトリです。

  6. ファイルを足して、add → commit → push

    エクスプローラーで python-practice フォルダを開き、置きたいファイルをコピーして入れます。そのあと Git Bash で次の3行を打ちます。

    git add .
git commit -m "Pythonの練習の答えを追加"
git push

    git add . の最後の点は「このフォルダの変更を全部」という意味です。-m の後ろの文が、このセーブポイントのメモになります。

    初めて git push したときだけ、ブラウザでGitHubにログインする画面が出ます。Git for Windows に一緒に入っている Git Credential Manager という仕組みが出しているもので、ここでログインを許可すれば以後は聞かれません。

    GitHubのリポジトリのページを開き直して、ファイルが増えていれば成功です。

黒い画面が苦手なら　GitHub Desktop

コマンドを打たずに、ボタンで同じことができる公式アプリ「GitHub Desktop」もあります（desktop.github.com から入れられます）。GitHubのアカウントでログインし、「Clone a repository」で持ってくる → ファイルを入れる → 左下にメモを書いて「Commit to main」→ 上の「Push origin」の順です。最初はこちらで慣れて、あとからコマンドに移るのでも十分です。面接では「普段はコマンドで操作しています」と言える方が強いので、少しずつ Git Bash も触っておくのがおすすめです。

5. 最初の練習　Pythonの答えを置いてみる

11月17日にお渡しした「Pythonの練習」の答えのファイルを、さっき作った python-practice リポジトリに置いてみましょう。手順4の6段目をそのまま行えば置けます。

置いたら、もう一歩だけ。GitHubの画面で README.md を開き、鉛筆のマークから「何の練習か」を2〜3行で書いて「Commit changes」を押してください。VBAで何をしていたか → それをPythonでどう書き直したかが一言あるだけで、面接官には前職の経験とつながった勉強だと伝わります。

GitHubの画面で直した場合は、手元のフォルダに反映するために、次に作業を始めるとき Git Bash で git pull を1回打ちます。

6. つまずきやすい所

「Please tell me who you are」と出てコミットできない

手順3の名前とメールアドレスの登録がまだです。手順3の2行を打ってから、もう一度 git commit すれば通ります。

push が断られる（ログインに失敗する・403 と出る）

GitHubのパスワードを直接打っても通りません。ブラウザのログイン画面で許可するのが正しい流れです。別のアカウントで一度ログインしてしまった場合は、Windowsの「資格情報マネージャー」を開き、「Windows資格情報」の中にある git:https://github.com を削除してから、もう一度 git push するとログイン画面が出直します。

push が「rejected」で断られる（GitHubの画面で README を直した後など）

GitHub側に手元にない新しい記録がある、という意味です。先に git pull で取ってきてから git push すれば通ります。

「not a git repository」と出る

いる場所がリポジトリのフォルダの外です。cd python-practice でフォルダの中に入ってから打ち直します。いまどこにいるかは pwd で確かめられます。

Publicのリポジトリは誰でも見られます。パスワード・社外秘のデータ・前職のファイルそのものは置かないでください。置くのは自分で書いた練習のコードだけにします。

分からないところで止まったら、出ている英語のメッセージをそのままLINEで送ってください。どこで止まっているか一緒に見ます。
