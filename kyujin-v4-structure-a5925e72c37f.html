0. ひとことで

求人票に書いてある事実は、求人1本ごとに1ファイルの「本体」へ全部まとまりました。1,127 本の求人すべてに本体があり、CA の口・コンソール・評価器は、この本体だけを読む作りになっています。

求人票に書いていない知識（先方からの連絡、武者野さんの裁定、在庫表の行）は「判定」として別に持ち、宛先で求人や枠に掛けます。事実と判定を混ぜないのが骨格の一番の決まりです。

  • 1,127求人の単位（unit）
  • 71,373事実（fact）の行
  • 32,679うち照合に使う行
  • 29,160照合の行で型の形あり
  • 370判定（yaml）

1. 全体の段

上から、会社 → 募集の枠と求人の単位 → 出し口（葉）→ 事実、の順に細かくなります。枠と求人は親子ではなく、「結び」で横につなぎます。1つの求人票に枠が2つ当たることも、1つの枠に求人票が10本並ぶこともあるからです。

実データの数: 会社の id が付いた unit は 1,028 本（会社 339 社）。付いていない 99 本は理由の記号を持っています（未解決 46・別に置く 31・あいまい 22）。葉を持つ unit は 133 本だけで、残り 994 本は葉が無く「unit そのものが1行」として読まれます。

枠は在庫表から作った対応表（docs/state/kyujin_slot_unit_map.json）に 350 枠あり、うち 229 枠が unit に結ばれています。まだ無い設計が鍵の正本にする追記型の登録簿（kyujin_slot_registry.jsonl）と、人が結んだ対だけを持つ「結びの台帳」は、main にまだファイルがありません。

2. 事実（fact）1つの中身

本物の1件をそのまま載せます（unit のハッシュは伏せました）。ある求人票の「年齢40歳までOK」という1行が、こういう形で入っています。この行は「未経験の人には40歳まで」という条件付きの必須条件として読まれます。

unit
mk-hanbai-••••••••MK 経路・販売職の求人票
fid
147取り込みで振る通し番号。値を直しても変わらず、欠番も使い回さない
key
age何の条件か。照合に使う key は 12（4 節）
value
{attr: age, op: le, value: 40}読んだ値
evidence
material: L1 / block: b4
「・年齢40歳までOK」どの資料のどの塊の、どの文か。71,373 行すべてが引用を持つ
frame_id
allどの出し口に当たるか。all＝この求人の全部の葉（設計の名は frames_at）
applies
experience = 未経験誰に当たる条件か。経験者にはこの上限は掛からない
strength
mustmust・target（歓迎）・ask（要相談）・null。✕ を作れるのは must だけ
as_of
2026-06-10源が言う日
shape
{form: range, max: 40}読み手が比べられる型の形。書けない行は代わりに unshapable（理由）を持つ
shape_v / by
norm-v3 / normalize型の版と、誰が書いたか

設計どおりに入っているもの: fid（71,373 行すべて）、evidence（すべて）、as_of（70,566 行・残りは日付が無く null）。照合の行は全部、shape か unshapable のどちらかを持っています。

設計と違う設計の欄名 frames_at は、実データでは frame_id という名で入っています（all が 56,080 行・葉の id が 15,293 行）。設計にある unknown（どの区分か源が言えない）は 0 行です。逆に実データには設計の表に無い scope（posting・frame・contract・company）が全行にあります。

3. 確からしさと印

確からしさの3段

確定求人票の原本から読んだ事実と、条件を6つ全部満たした判定（証言者・日付・期限・届き方・型・宛先・経路が揃ったもの）。
先方に聞く源が割れている、誰が言ったか分からない、期限が切れた、会社宛てでどの出し口の話か決まらないもの。
参考自分たちの写し（在庫表・カードの行）、別の経路の資料、公開サイトを読んだもの。隠さず札を付けて出します。

印は6つ

  • ⭕出せる
  • △年収・休日・夜勤などに差がある。落とさない
  • ？本人求職者の欄が空。本人に聞けば決まる
  • ？先方先方に聞かないと決まらない
  • ？機械型の形が無い・写せない。機械の側の欠け
  • ✕物理的に無理なものだけ。出典つきの must か、名のある「募集終了」からしか出ない

経験・免許・勤務地からは ✕ を出しません。証言者の分からない判定も ✕ にはならず、最大で ？先方 です。

食い違ったときの優先順

同じ出し口・同じ key に矛盾する値が2つ以上あるとき、上から勝ちます。負けた側も消さず、「食い違い」の札を付けて直下に出します。

  1. 武者野さんの裁定。宛先が粗くても、期限が切れていても勝つ
  2. 細かい対象が粗い対象に勝つ（葉 ＞ unit 全体 ＞ 枠 ＞ 会社 ＞ 経路 ＞ 全社）。ただし細かい側が具体の値を言うときだけ
  3. 確定した判定（6条件を満たすもの）
  4. 求人票の事実（型の形つき）。同じ順位なら源の日付が新しい方

まだ無い判定を読む側の優先の順と広い宛先の読みは、読み手の関数がまだ書かれていません。判定 370 本のうち型つきの中身（value.fact）を持つのは 15 本（全部が制約）で、証言者が「不明」の判定が 211 本あります。

4. 12 の照合キー

CA の問い（この人にこの求人を出せるか）と結ぶ欄は、次の 12 だけです。在宅勤務は照合に入れません。棒は、その key の行のうち型の形が付いている割合です。

  • work_location 勤務地18,279 行・形あり 94%
  • experience 経験4,387 行・形あり 85%
  • status 募集の開閉2,349 行・形あり 98%
  • age 年齢1,910 行・形あり 95%
  • education 学歴1,492 行・形あり 95%
  • nationality 国籍1,260 行・形あり 90%
  • ng NG 条件859 行・形あり 15%
  • residence 住まい724 行・形あり 49%
  • availability 勤務の可否（出張・土日など）508 行・形あり 52%
  • qualification 資格・免許387 行・形あり 74%
  • gender 性別375 行・形あり 93%
  • grad 卒業の区分（新卒など）149 行・形あり 85%

形の無い行は「書けない理由」（unshapable）を持っていて、形も理由も無い行は 0 です。ng・residence・availability は、源の書き方が自由文に寄るぶん、理由つきで形を見送った行が多くなっています。

5. 書き込みの口と読み口

本体を書き換える道は1つだけです。どの書き手も同じ口を通り、まず dry-run で「何がどう変わるか」を出し、--execute を付けたときだけ書きます。引用と値はどの操作でも書き換えられません（門が止めます）。

本体は上書きで、いまの版だけを持ちます。前の版は退避（body_prev/）と操作の記録（body_ops/・{unit, fid, op, before, after, by, at, 版}）にあり、記録は消しません。いま GCS には操作の記録が 20 本、退避が 19 回分あります。

型の形を書く手は2つです。求人が届いた瞬間に規則で書ける分を書き、残りは月額枠のセッションがまとめて読んで書きます。目録の owed（形も理由も無い照合の行の数）は、いま全 unit で 0 です。

7. まだ言えないこと

  • 中身が正しいかは、抜き取りでしか確かめていません。形が「付いている」ことは全数で数えましたが、その形が求人票の意味どおりかは、受け入れ試験の求人と監査の抜き取りで見ただけです。
  • 受け入れ試験は 34 本中 20 本が合っています。8 本は既知の外れ（xfail）で、内訳は形の欠けが ZT4 の1本、箱にまだ求人票が無いものが 7 本。残る 6 本は正しい答えが決まらないので保留（skip）にしています。
  • CA の問いをどれだけ答えられるかは、測り直していません。11-19 に問い 66 型 × 求人票 1,134 本で撃ったときは「決まる」が 28.8% でした。その後に形を全経路へ書いたので数は動いているはずですが、まだ撃っていません。
  • 読み手の関数で、まだ無いもの: 判定の優先の順と広い宛先、通勤（read_commute）、転勤、短期離職、再応募、市区町村。勤務地から ✕ が出ないのはこのためです。
設計にあって、実データにまだ無いもの
  • frames_at は実データでは frame_id という名。値 unknown は 0 行
  • 源の写しの channel（どの経路の資料か）と shareable（本人に渡せるか）は、3,525 件のどれにも無い
  • 枠の登録簿 kyujin_slot_registry.jsonl と結びの台帳は、まだファイルが無い（在庫表から作った 350 枠の対応表はある）
  • 判定の型つきの中身 value.fact は 370 本中 15 本だけ
  • unit の発行の種別 unread・no_material は、目録の理由の記号に現れない
