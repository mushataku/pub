1. 全体の地図

色の付いた枠が「動いている場所」、矢印が「誰が誰に何を頼むか」。

それぞれの場所の役

場所ここにあるもの
Discord連絡の場所。依頼の掲示板（仕様フォーラム）と、Claude が書き込むための Bot。Discord 社のサーバで動く。
拓也の PC見回り係（5分ごとに掲示板を見る）、Claude（調べて直す）、Pixel（実機のスマホ）、手元の Chrome、鍵の引き出し。PC が止まると、ここにあるもの全部が止まる。
Google Cloudゆうとが押す操作画面（LinksMate コンソール）と、その周り（口座の状態の写し・パスワードの金庫・ログ）。いまは1台・CPU 1個（CPU＝計算する係。4章のたとえでは「店員」）。
LinksMate本物の申込画面。コンソールがブラウザを自動で動かして、ここで申し込む・解約する。

2. ゆうとの依頼が直るまでの流れ

  1. Discordゆうとが仕様フォーラムに書く「不具合です」「こうしたい」。
  2. PC見回り係が5分ごとに見に来る最後の発言が人（Bot ではない）の投稿を「返事待ち」として見つける。
  3. PCDiscord拾い手の Claude を起こす起きた Claude は「拾いました」と返信し、投稿の札を「対応中」にする。
  4. PCGoogle Cloud事実を集めて直すログや写しを読んで原因を確かめてから直す。大きい修正は別の Claude に渡し、終わるまで見届ける。
  5. GitHub着地直したコードを、共有の本棚（GitHub）の本線に載せる。
  6. Google Cloudデプロイ新しい版を Google Cloud に置いて切り替える。作業中の口座があれば、終わるまで待ってから切り替える。
  7. Discordゆうとに返信何が起きていて、何を直したかを、ゆうとに分かる言葉で書く。
  8. Discord札を「済」にゆうとが続きを書けば、見回り係がまた拾う（1 に戻る）。

2〜4 は PC の上で起きる。PC が止まると、この流れは 2 で止まる（9月24日の出来事 A）。

3. 9月24日（水）の3つの出来事を地図の上で

起きた順は C（17:07〜）→ B（17:39）→ A（18:47〜）。下は影響の大きい順に A から書いた。

APC が固まった（18:47〜23:00）

地図のどこで
拓也の PC
何が起きた
PC が固まって再起動し、見回り係も一緒に止まった。19:33 のゆうとの投稿を拾うのが約3時間半遅れた。止まる直前に拾った Claude は「拾いました」とだけ返して落ち、その投稿には5時間半返事がなかった。
このあいだもコンソールは動いていた（Google Cloud 側なので）。
何を直した
  • 「拾いました」の一言だけで落ちた担当を、見回り係が見つけて拾い直す（着地済み）
  • 電源が戻ったら PC が自分で起動する設定を入れた（ただし今回は停電ではなく「固まり」だったので、この設定では救えない）
  • PC の外の控え（クラウドの代打）を作って、寝かせてある（4 章）
まだ残っていること
固まったときに戻す手（未設計）／ログオンしなくても見回り係が動くか（実測待ち）／代打を起こす承認

B版の切り替えがジョブの途中に当たった（17:39）

地図のどこで
Google Cloud のコンソール
何が起きた
17:36 に、ある口座で「回線を4本追加」を始めた。17:39 に、直前の不具合を直した新しい版へ切り替えた。新しい版は古い版の作業を知らないので、画面は「0/4本 で中止」と出した。
実際は古い版が裏で作業を続けていて、3本申し込んでいた（4本目は、古い版が止まったときに消えた）。
何を直した
  • 切り替えの前に、全部の口座の作業が終わるのを待つ
  • 待っている間は新しい注文を断る（受付停止＝画面に「更新のため数分お待ちください」）
  • どの版で作業が走っているかの目印を写しに置き、古い版の作業中は押せなくする
  • 作業を見失ったら「中止」と言わず、「見えなくなりました。サイトから読み直して」と正直に出す
  • 本線に載っていない古いコードから版を作らせない門

C混み合い「429」（17:07〜17:36 に26回）

地図のどこで
Google Cloud のコンソールの入口
何が起きた
ブラウザの自動操作を起動するたびに、1個しかない CPU が埋まった。そのあいだ入口が「混み合っています（429）」を返した（長いときで約1分）。
断られた操作は中まで届いていないので、二重の申込にはならない。PC や Claude のアカウントは関係ない。
何を直した
画面が最長約65秒、自動でやり直して待つ（「押し直さなくて大丈夫です」と出る）。
まだ残っていること
根っこは「CPU 1個」。打ち手は次の章。

4. 打ち手の違い

混み合い: 店員1人のお店で考える

お店コンソール
店員CPU（いま1人）
レジ（お客さんに返事する）画面の応答（押したら返事する）
調理（時間がかかる）ブラウザの自動操作（申込・解約）
注文メモどの口座で何が進行中か
伝票ボードキュー（順番待ちの列）。いまは無い。③で置く

PC が止まったとき

PC が止まっている間、ゆうとは
できる: コンソールで申込・解約を押す／Discord に書く
できない: 依頼を拾ってもらう・直してもらう・返信をもらう（③の代打を起こせば、PC の道具が要らない依頼は拾えるようになる）

拓也の裁定と、いま進んでいる票

2つの話で、それぞれ別の番号の付いた手がある。

  • 混み合い（①大きくする ②台数を増やす ③係を分ける）→ 拓也の裁定は「①と③をやる」（9月25日 02:54）
  • PC が止まったとき（①自動復帰 ③クラウドの代打）→ 拓也の裁定は「①と③をやる」（9月25日 01:23）
打ち手いまの状態（9月25日 03:50）
混み合い ① CPU を2個に進行中。設定を変えて、その後1週間「429」の回数を数えて効いたか確かめる（数えるのは機械が予約する）
混み合い ② 台数を増やすやらない。③で注文メモを外に出した後なら、できるようになる
混み合い ③ 係を分ける設計中。設計書と、最初の段の作業の票を作っている。本番はまだ変えない
PC停止 ① 自動復帰途中。電源が戻ったら起動する設定は済み。固まったときに戻す手は未設計。ログオンなしで見回り係を動かせるかは実測待ち
PC停止 ③ クラウドの代打作って寝かせてある。起こすには、月約180円の承認と、拓也の web での設定（代打の Claude の登録）が要る

拓也向けの一言: 律速段階は「CPU 1個をレジと調理で取り合う」ところ。① はその段の速度を上げる、③ は経路を2本に分けて取り合いそのものを消す。② は並列につなぐ手だが、注文メモ（状態）が各経路で別々に数えられて二重になる。

5. お金の流れ

12月までにゆうとがやること: 1つだけ
12月に入ったら、ゆうとの Google アカウントで Google Cloud の請求の画面を開き、「有料アカウントに切り替え」を押す。ゆうとにしかできない操作（本人のログインが要る）なので、時期が来たら Claude から Discord の「決済のお願い」で頼む。
何に誰の請求いくら
Google Cloud（コンソールなど全部）ゆうとの請求アカウント（いまはクレジットから）実額は未確認。9月25日にこの資料を作ったとき、請求の明細の読み出しが返ってこなかった。CPU を2個にする作業の中で、明細を読み直して実額を出す
└ CPU を2個にした分同上見積り 月に約1,300〜1,700円増（1日に何時間動くかで変わる）
└ PC停止時の見張り（まだ起こしていない）同上見積り 月に約180円（承認待ち）
Claude のセッション拓也の Claude の定額プラン定額（使った分だけ増える請求ではない）
Discord—無料
LinksMate の回線・ポイント各口座この資料の外（お金が動く操作は別の門で守っている）

6. 用語集

Cloud Run
Google が貸してくれる「呼ばれたときだけ起きるサーバ」。コンソールはここで動いている。
インスタンス
そのサーバの1台ぶん。いまは1台だけ（お店1軒）。
CPU
計算をする係。お店でいう店員。いまは1個（1人）。
デプロイ
直した版をサーバに置いて、切り替えること。お店でいう改装。
版（リビジョン）
デプロイのたびにできる、番号付きの版。まずかったら前の版に戻せる。
429
「混み合っているので受け付けられません」という返事の番号。入口で断られていて、中には届いていない。
キュー
順番待ちの列。お店でいう伝票ボード。
心拍
「生きてるよ」と決まった間隔で出す合図。途絶えたら止まったと分かる。
見張り
Google Cloud で5分ごとに PC の心拍を確かめる小さなプログラム。心拍が15分来なければ代打を起こす（まだ寝かせてある）。PC の「見回り係」とは別物。
フェイルオーバー
いつもの係が止まったら、控えが代わりに動くこと。野球の代打。
受付停止
デプロイの前に新しい注文だけを止めて、作りかけは最後まで作らせること。
写し
口座ごとの今の状態を、Google Cloud の保管庫に置いたもの。画面を開いた瞬間にこれを出す。
鍵の金庫
パスワード類をしまっておく Google Cloud の金庫（Google での呼び名は Secret Manager）。
見回り係（spec_watch）
拓也の PC で5分ごとに仕様フォーラムを見回るプログラム。
着地
直したコードを、共有の本棚（GitHub）の本線に載せること。デプロイはその後。
