Pixel の Gboard の鍵を1つずつ押して打つと、ページからどう見えるか

自陣の localhost ページを Pixel 7a の Chrome で開いて測定（実サイトには触っていない）。各図の棒＝平均・黒線＝±SE。

結論（cont3・2026-10-06 08:15 の撃ち）
  • QWERTY（設定「英字入力は QWERTY」を一時 on）: K4q 2/2 一致・20 字 4.32±0.13 秒。位置決めは (a)(b)(c) とも 26/26。撃った後に off へ戻し、off と読んで確かめた
  • cont2 で QWERTY の段に3回とも鍵盤が出なかった原因は、校正が前のページの古い記録（入力欄を押した記録）を拾って座標がずれていたこと（BACK ではない）
  • かなの後の空白は「変換」になる（'あ い'→'亜い'）。確定してからかなのまま押すと全角空白。英字へ回して押す形にして 'てすと あいう' が一致（KT3）
  • type は打った後に入力欄を uiautomator で読み返して [OK]/[NG] を出す。今回の8本は読み返しの判定がページの最終値と全部合った（KJ は変換ありで比べない）
  • 表の「端末側1字」「字間隔」は族ごとの字数で割った（cont2 の KJ の 24ms は 19 で割った誤り）

問3 鍵を押して打つのを人の速さにできるか（遅さを押し方と配列に切り分ける）

問3 20 字を打ち終えるまでの秒（ページが見た最初の keydown→最後の keydown）

人の速さの目安は 20 字で 約 4〜6 秒（字間隔 200〜300ms）。K4m と K4f は押す1回ごとの間隔を同じ人の分布（lib/human_motion の打鍵・中央値 190ms）から引いた＝差は配列（多タップ 47 回 vs フリック 20 回）だけ。K4 と K4z の差は押し方（1押しごとの adb）だけ。

問4 1回押すのにかかる時間の内訳（画面に触らない計測）

adb_true＝adb shell true（PC↔端末の往復だけ）・adb_input＝adb shell input keyevent 0（PC から input を1回）・input_in_shell＝端末の中で input keyevent 0 を続けて撃つ1回あたり・inj_start＝注入器の起動（押す列 0 個・1回だけ払う）。この端末の input は `cmd input` を呼ぶシェル（JVM は立たない）。K4 の1押し 約150ms は adb の往復と cmd input の処理の和。注入器は起動を1回だけ払い、その後の押下には上乗せが無い。

問1 Gboard の鍵の位置を機械で決められるか

問1 位置決めの手ごとの、dump と一致した字の数（qwerty）

英字モードの鍵盤（qwerty）で、各手が決めた点が dump の鍵の矩形に入り、タップ回数も同じ字を数えた。(a) は基準そのもの＝拾えた字の数。欠け: (a) dump の node なし・(b) 窓の矩形×格子 なし・(c) スクショの白い鍵 なし

問1 位置決めの手ごとの、dump と一致した字の数（12key）

英字モードの鍵盤（12key）で、各手が決めた点が dump の鍵の矩形に入り、タップ回数も同じ字を数えた。(a) は基準そのもの＝拾えた字の数。欠け: (a) dump の node なし・(b) 窓の矩形×格子 なし・(c) スクショの白い鍵 なし

問2 鍵を押して打った文字は、K1/K2 と何が違うか

問2 押下の間隔（ページが見た keydown→keydown）

K4 系は鍵を押すたび（多タップの2回目・3回目、→・大文字・「あa1」も）に keydown が出る＝字の間隔ではなく押下の間隔。K4 は adb input tap を1回ずつ（1押し 約150ms＝下の問4）。K4z/K4m/K4f/K4q は注入器が端末の時計で押す（K4z は人の間隔の 1/4）。K1 は delay=120ms の指定どおり揃う。SE は全本の間隔をまとめた値（本の中の間隔を独立とみなす）。

問2 入力欄の最終値が打った文字列と一致した割合

KJ は「てすと」か「テスト」で一致。SE は √(p(1-p)/n)（n は各腕の本数）。
