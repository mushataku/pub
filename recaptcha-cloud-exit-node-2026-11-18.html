クラウドの Job を家の回線の exit node から出す（reCAPTCHA の即時通過）

2026-11-18。前の2段で、クラウドの Job（GCP の IP）から公開の的を撃つと即時通過が 0/16、PC の家回線から同じ的を撃つと 16/16 だった＝落としているのは出口の IP。今回は Job はクラウドのまま、通信だけを Tailscale の exit node で家の回線へ回した（鍵 fresh2・headed・cdp_human＋音声・n=16 を撃つ前に固定）。

結論

GCP→家の即時通過は 13/16（95% 区間 0.57〜0.93）。GCP×公開の 0/16 との差は +0.81（区間 +0.50〜+0.93）＝出口を家の回線へ回すだけで即時通過の大半が戻る。PC×公開（16/16）との差は +0.19（区間 −0.04〜+0.43）で 0 をまたぐ＝この n では「PC から直接撃つのと同じ」とも「少し落ちる」とも言い切れない（差があっても 0.43 以内）。音声込みのトークンは 16/16 で、どのマスとも区間が重なる。

段B 携帯回線の exit node（未測定）

携帯の回線から出す段は撃っていない。exit node にする端末の候補が2台あり、どちらも今日は使えなかった。

端末止めた理由
青い Pixel 7aモバイルのデータの送受信が 0 で、Wi-Fi を切ると tailnet から見えなくなった。Wi-Fi は入った状態に戻っている（電池 48%・27℃）。
黒い Pixel 7aモバイルの通信はあるが、回線は人材の事業のもので、従量の料金がかかるか分からない＝課金の判断が要る。撃っていない。

撃つ前の門は、携帯回線かどうかを回線会社の名前で決めない形に直した（格安の回線は大手の名前で出ない。家の回線と同じ会社名のこともある）。端末の Wi-Fi を切ってから端末そのもので読んだ IP と、Job が exit node 越しに読んだ IP が一致したときだけ撃つ。

撃ち方と限界

n=16 を撃つ前に固定し、途中で止めず撃ち足さなかった。撃つ前の門で出口の IP を読み、家の回線と一致してから撃った。測り終えて PC の exit node の広告と承認を外し、Job の env を既定へ戻した。

  • 音声の取りに行き（音声チャレンジの mp3）は exit node を通らず GCP から出ている。トークン取得率のマスは、この分だけ純粋な比較ではない。
  • 名前解決が SOCKS 越しか GCP 側かは確かめていない。
  • WebRTC の UDP は SOCKS を通らない（Chrome の既定では漏れうる）。
