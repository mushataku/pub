Astroってなに？ 図解でざっくり

「GitHubのrepoって何？」「素のHTMLと何が違うの？」をゼロから図で確認する用の1枚。2026-10-11 作成。

① そもそも「GitHubのrepo」「フォルダ」ってどういう状態？

さっき見てもらった実例（チケット風ページ）のフォルダを、そのまま箱の絵にするとこう。

  • 📦 epl（リポジトリ＝この一式が入ってる大きい箱）
    • 📁 _astro（部品が組み上がった後のCSS・JS）
    • 📁 image（ボタンの画像とか）
    • 📁 tickets（チケットのページが並ぶ場所）
      • 📁 8a6e2443-...（1人ぶんのチケット＝フォルダ名がランダムな文字列）
        • 📄 index.html これがブラウザに表示される実体
        • 📁 mogiri（もぎり画面）
      • 📁 （他の人のチケットがあれば、ここにもう1個フォルダが並ぶ）
ポイント： GitHubの画面（github.com/...）で開くと、この「箱の中身」がソースコードのまま見える。
GitHub Pagesの画面（....github.io/...）で開くと、index.htmlの中身がブラウザで「組み立てられて」ふつうのWebページとして表示される。
同じファイルを、2つの違う見方で見ている、というだけ。

② 素のHTMLとAstro、何が違うのか

「最終的にブラウザに出てくるもの」はほぼ同じ。違うのは「作るときの手間」。例：100人ぶんのチケットページを作るとする。

素のHTML手でコピペして増やす

<header>ロゴ...</header>
田中さん用の内容...
<header>ロゴ...</header>
佐藤さん用の内容...
… これが100人ぶん続く …
👉 ヘッダーのデザインを1つ直したくなったら、100個のファイルを全部開いて直す

Astro部品化してビルドで量産

部品：Header.astro（1個だけ書く）
テンプレ：チケットの型 + 名簿データ（田中さん、佐藤さん…）
⬇ ビルド（機械が自動で流し込む）⬇
tanaka/index.html, sato/index.html … が自動で生成される
👉 ヘッダーを直したくなったら、部品1個だけ直せば100人ぶんに反映される

③ さっきのチケットのフォルダ名がランダムだった理由

テンプレート（枠）とデータ（中身）を分けて、ビルドのときに「1人1フォルダ」で量産しているから。

テンプレート
index.astro
（枠だけ・名前や日付は空欄）
＋
名前:A さん
名前:B さん
名前:C さん…
⬇
ビルド
📁 ランダムID-1
（Aさんの1枚）
📁 ランダムID-2
（Bさんの1枚）
📁 ランダムID-3
（Cさんの1枚）

※フォルダ名をランダムにしているのは「連番だと他人のチケットのURLを推測して覗けてしまう」のを防ぐため。中身（名前・金額など）はビルドの時点でもう確定したHTMLとして書き込まれている＝あとから動くプログラムではない。

まとめ

用語意味
リポジトリ(repo)ファイル一式が入った箱。GitHub上の「プロジェクトのフォルダ」
ソースコード人間が書く「元の設計図」。Astroの場合は .astro ファイル
ビルド設計図を実際に動くHTML/CSS/JSに変換する作業（機械が自動でやる）
ビルド後の静的ファイルブラウザがそのまま表示できる完成品。GitHub Pagesに置くのはコレ
GitHub Pagesrepoの中身を無料でWebページとして公開してくれる機能
一言でいうと： 素のHTMLは「1枚ずつ手で作る」。Astroは「型を1個作って、データを流し込んで量産する印刷機」。
1枚しか要らないならAstroは要らない。何十枚・何百枚を似たデザインで作るときに手間が大きく変わる。
